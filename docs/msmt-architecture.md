# MSMT：跨平台移动设备自动化架构

更新日期：2026-10-27

状态：架构提案，包含独立的模拟 MVP。MSMT（Microsoft Mobile Test）为暂定名称，不代表产品发布承诺。

本文从原 iOS 集成项目的 MSIT 设计迁移、调整而来，将 iOS Runner 的权限模型扩展为 Windows/macOS 上的 Android/iOS 公共服务架构。原项目文档保留作为设计历史；本文是本仓库后续讨论的入口。相关讨论：[架构 issue #5](https://github.com/microsoft/mobile-use/issues/5)。

**本地 `develop` 工作区只保留 MSMT 文档与模拟 MVP。** 旧 Android/ADB 插件、十三个 MCP 工具及打包实现已从本工作区移除，历史仍保留在 `main`；本 demo 不连接设备，也不代表旧插件获得了新的授权机制。

## 1. 为什么统一设计

现有 Android POC 通过 ADB 控制设备，不需要自有手机端 Runner。iOS 则需要签名 XCTest Runner，以及开发者连接、部署、启动与清理流程。宿主 Windows/macOS 的工具发现、IPC 和签名构建能力也不同。

如果把这些差异继续放进同一个 MCP 会话类，就会混合平台生命周期、设备选择、任务权限和数据观察，难以说明哪些能力真正获得授权。

另一个问题是隐私：不读取 App 私有存储不代表不接触用户数据。截图、UI 树、App 列表、前台信息和错误诊断都可能泄露内容。允许打开 App、点击控件，不自动意味着允许读取登录后的余额、账号或消息。

核心决策：

1. 统一任务、授权和操作语义，不强求相同的平台执行组件。
2. 公共 Host Service 持有策略；MCP 和 CLI 是受限客户端，不直接调用原始驱动。
3. 操作、观察、生命周期权限分开，用户确认不由模型自行声明。
4. 隐私接管必须停止采集和自动操作，不只要求 Agent 避开敏感页面。
5. 复用现有 ADB 实现与 WDA 执行能力，逐步建立边界，不从零重写驱动。

## 2. 目标、非目标和信任假设

目标是在 Windows/macOS 上，允许 Agent 在有限、可撤销的授权下操作 Android/iOS 真机。平台能力和强制边界必须明确报告。

不承诺个人设备上的完整系统隔离、多租户隔离、通用敏感信息识别或所有平台组合已经可用。不绕过锁屏、生物识别、系统权限、设备管理策略和开发者授权。

| 组件 | 定位 |
| --- | --- |
| Agent、生成的参数、设备页面内容 | 不可信，不能修改策略或证明人类同意 |
| MCP Server / CLI | 公开接口映射，不持有签发密钥或原始驱动能力 |
| Host Service / 可信确认界面 | 可信计算基，管理任务、设备、授权和输出 |
| Platform Adapter | 可信平台执行代码，不能自行扩大权限 |
| 受控 iOS Runner | 可独立验证授权、拒绝动作和采集的设备端执行点 |

若 Agent 能任意读取 Service 私钥、调用 ADB/开发者服务或自行部署其他 Runner，就可能绕开 MSMT。独立服务应采用宿主身份隔离和已认证 IPC；随机句柄、隐藏端口和 loopback 本身不是充分的身份隔离。

## 3. 总体架构

```text
Copilot / 其他 Agent                 用户
         |                            |
         | MCP                        | 可信确认 / 接管 / 恢复
         v                            v
   MSMT MCP Server               Approval UI
         |                            |
         +-------------+--------------+
                       | 已认证本机 IPC
                       v
               MSMT Host Service
   Device Registry / Task / Lease / Grant / Policy
        Scheduler / Privacy State / Output Gate
                       |
              私有 Platform Adapter
                 /             \
        Android Adapter      iOS Adapter
               |                 |
              ADB         go-ios / 开发者服务
               |                 |
        Android 系统能力    签名 XCTest Runner
                           + 设备端 Policy Gate
```

Copilot 是 MCP Client，MSMT 暴露 MCP Server。后续 CLI 同样经过 Host Service，不能形成另一条直连设备的路径。

逻辑分层先于进程拆分；首个原型可以进程内验证协议。持久后台 Service 引入时，必须同时解决调用者认证、所有权、断线撤销和清理，不能仅删除旧的关闭处理。

## 4. 平台差异与支持矩阵

| 模式 | 权限执行位置 | 说明 |
| --- | --- | --- |
| Android / ADB | Host Service + Adapter | 无需自有 Runner，只约束经过 MSMT 的调用 |
| iOS / 原始 WDA 过渡模式 | Host Service + Adapter | 不声称原始 WDA 会验证 MSMT Grant |
| iOS / 受控 Runner | Host Service + Runner | Runner 可再次拒绝未授权采集和操作 |

统一 API 不等于相同的隔离保证。能力中应分别声明平台功能和 `host` / `host-and-runner` 等执行模式，不因连接 iOS 就自动声称存在设备端保护。

| 宿主 | Android | iOS |
| --- | --- | --- |
| Windows | 后续从 `main` 历史提取 ADB 适配实现 | 开发者服务及兼容的已签名 Runner；签名部署单独验收 |
| macOS | 适配 ADB 路径、发现及宿主检查 | 开发者服务，以及适用的 Xcode 构建/签名/部署 |

以上为目标矩阵，不是已验证支持清单。Windows 不能替代 Xcode 从源码构建 iOS Runner。自研仍需 Apple 签名、profile、开发者模式和设备信任；开源许可证与这些要求是独立问题。

WDA 可作为首选 iOS 执行层复用对象；DeviceKit 可提供设计参考。任何代码复用都需核对具体版本许可，保留来源与适用声明。

## 5. 公共对象和授权模型

| 对象 | 含义 |
| --- | --- |
| Device | 可确认的物理设备身份 |
| Endpoint | USB/Wi-Fi 等具体连接；一个设备可以有多个 Endpoint |
| Task | 用户授权的工作范围 |
| Lease | 某客户端任务对某设备的有限使用权 |
| Grant | 操作、观察通道、目标范围、期限及授权版本 |
| Observation | 绑定任务、授权版本和上下文的数据与引用 |
| ActionResult | 提交状态、验证状态、不确定性 |

设备选中 token 不等于 Grant。禁止根据型号、默认端口或第一台设备隐式选择，断线不自动切换 Endpoint。一个设备一个活动租约；跨设备任务分别授权，不提供虚假的整体事务回滚。

完整 Grant 应绑定任务、设备、宿主会话、Runner 实例（如存在）、策略版本、授权版本、范围、有效期和批准请求。可信组件维护到期与一次性消费状态，模型不持有签发能力。

可信控制面负责批准、恢复、缩权和撤销；Agent 只能请求。批准不能是一个模型可自行填写的 `confirmed: true`。具体动作确认要绑定目标、参数和上下文，变化后不能沿用旧确认。

Copilot 的交互能力需要协商验证；不支持时使用独立可信界面，不降级为模型自证。客户端权限 UI 有价值，但不能代替 Service 对任务范围的校验。

## 6. 操作与观察独立

```text
公开请求 -> 当前授权检查 -> 排队 -> 执行前复核
                                     |
                        平台执行 / 获准的数据采集
                                     |
                      设备端输出检查（如支持）
                                     |
                         Host 输出复核 -> Agent
```

观察通道包括截图、语义树、流、App 元数据，以及错误、日志、诊断和导出。内部校验读取也受策略约束，不能为了“动作安全”而无条件截图。

`act()` 不自动赋予 `observe()` 权限。可以提供动作后观察的便捷流程，但必须独立检查；动作已提交而观察被拒绝时分别报告，不自动重试。

保护强度应区分：

- 禁止采集：隐私接管期默认方式。
- 可信侧采集但不交付：原始数据仍进入可信计算基，不能称为没有采集。
- 脱敏后交付：附加保护，不是完整 DLP/PII 保证。

密码、验证码等已知控件可结构化保护，但静态账号、余额、消息不一定能识别。App 白名单、OCR 和前台检查都不能保证截图内容只属于获准 App；前台检查与采集不原子，通知和用户切换仍有竞态。

待交付结果绑定 `taskId`、设备、授权版本、上下文、通道和采集时间；输出前复核，拒绝撤销前启动、撤销后返回的数据。已经交付的数据无法收回。默认不落盘、不发送原始内容遥测，并限制缓存和诊断输出。

## 7. 隐私接管与执行状态

```text
WAITING_APPROVAL -> ACTIVE
ACTIVE -> PRIVATE_HANDOFF -> WAITING_RESUME -> ACTIVE
任意非终态 -> SUSPENDED / EXPIRED / REVOKED / CLOSED
```

接管流程：

1. 先关闭新操作和采集，提升授权版本，使旧引用和结果失效。
2. 取消待执行请求，停止流，丢弃尚未交付的结果。
3. 结算在途动作；已进入系统的输入可能无法取消，报告已提交或不确定。
4. 设备/宿主闸门及在途处理完成后，才能通知用户可以手动处理敏感内容。
5. 用户退出敏感上下文，通过可信界面恢复；登录成功或模型声称完成不能恢复。
6. 新授权版本和新上下文生效，旧请求不重放。

撤销/接管更新不能排在长任务后面才生效。恢复预览也不能未经授权先截图。客户端断开需撤销其任务和租约，不影响其他客户端；Service 继续存在不意味着授权继续有效。

## 8. 平台操作、引用和失败语义

基本接口围绕任务提供观察、受限动作、状态、接管和关闭。安装、卸载、特定输入、WebView 和流等按能力扩展，不偷偷使用键盘/helper/剪贴板回退。

引用绑定设备、任务、授权版本、App、上下文和目标。失效返回明确错误，不把旧编号映射到新元素。属性相同不证明底层对象相同；iOS 没有通用等同浏览器 document epoch 的页面版本。坐标操作需要独立范围、近期观察和几何校验。

动作结果区分 `not_committed` / `committed` / `unknown`；提交不等于业务成功。授权拒绝、接管、上下文过期、断线和未知结果不能变成空成功，也不能自动重试可能已执行的动作。公开错误不夹带原始页面或输入。

Android Adapter 保留 transport 绑定、几何/旋转复核、受限输入与保守错误语义。受控 WDA Runner 必须关闭原始路由、备用端口、流、诊断和扩展命令等旁路；仅给常用 HTTP 路由加校验不够。

## 9. 本分支的最小模拟 demo

运行：

```powershell
npm run demo:msmt
```

入口：`src\msmt\demo.ts`；公共核心：`src\msmt\service.ts`；用例：`test\msmt.test.ts`。

demo 使用两个固定的 Android/iOS 模拟适配器，不读取手机、ADB、网络、屏幕、私钥或用户文件。它演示：

- 同一公共接口路由到不同平台；每台设备只有一个活动任务租约。
- Agent 入口申请任务，但不能批准、恢复、撤销或修改 Grant。
- 可信控制入口批准请求；范围固定，单调时钟租约到期后失效。
- `launch_app` 与 `ui_tree` 分开授权，动作不会自动观察。
- 接管立即拒绝新操作，等待队列结算，再报告屏障完成。
- 输出前校验授权版本，丢弃在途旧结果；恢复后不重放。
- 未获准 App 的观察不交付；这只是可信侧过滤，不证明采集前隔离。

demo 仅演示启动 App 与合成 UI 文本，所有适配器均声明 `host` 执行。**iOS 模拟器不代表已实现 Runner 或设备端校验。**

Agent/Control 是进程内不同对象，可信调用方负责不把 Control 交给模型。这只是接口职责分离，不是抵御同进程恶意代码的安全沙盒。没有 MCP 接线、可信 UI、真实 IPC、签名 Grant、Runner、持久后台进程或硬件支持，也没有完成全部采集超时/取消能力。接管必须等在途模拟调用结束，不能承诺立即中止物理操作。

本分支没有 MCP 插件或原 `MobileUseService`。旧实现保留在 `main` 历史中；后续接入必须经过此授权模型，不能恢复未受控的旧工具旁路。

## 10. 渐进路线与验收

1. 在精简的 MSMT 项目中验证公共模型和状态机，旧实现保留在 `main` 历史中。
2. 按需从历史实现提取 Android Adapter，把动作内部读取纳入观察策略；适配跨平台错误和能力，不直接复制原 MCP 会话层。
3. 加入 iOS Adapter、宿主平台实现与独立验收记录，不把未验证矩阵标成支持。
4. 接入可信确认、MCP、任务所有权、已认证 IPC 和后台服务生命周期。
5. 将设备端执行点加入受控 iOS Runner，关闭所有原始旁路。

最小验收要求包括：批准前不触及 Adapter；操作权限不隐含观察；接管/撤销拒绝新请求并丢弃旧结果；过期和跨设备任务失败；单设备独占；在途动作不伪装撤销；恢复不重放；错误不泄露原文。

真机阶段另行验证断线、重启、通知、App 切换、系统弹窗和可信界面不可用等情形；模拟测试不能作为真机隔离证明。

不变量：**所有设备调用经过权限检查，所有内容输出经过观察授权；Agent 不能自行批准或解除人工接管。**
